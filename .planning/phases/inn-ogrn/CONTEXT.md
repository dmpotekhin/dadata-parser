# Контекст: выбор идентификатора ИНН/ОГРН для поиска в DaData

Статус: реализовано, ждёт ревью/коммита.

## Задача (из ТЗ пользователя)

Доработать логику выбора идентификатора: сначала ИНН, затем ОГРН/ОГРНИП,
иначе строка помечается invalid_id. Режим `--search-by auto` — по умолчанию.

## Принятые решения

* Типы идентификаторов: `inn` (10/12 цифр), `ogrn` (13), `ogrnip` (15);
  значения хранятся как ключи кэша `inn:<номер>`, `ogrn:<номер>`, `ogrnip:<номер>`.
* Старые ключи state-файла (голый ИНН) мигрируют к `inn:…` при загрузке,
  порядок сохраняется, дубликаты убираются; в state появилось поле `version: 2`.
* Статусы `invalid_inn`/`empty_inn` заменены на `invalid_id` (детали — в колонках
  «Причина выбора идентификатора» и «Ошибка»); запрос по таким строкам не уходит.
* `--fallback-to-ogrn` срабатывает на `not_found` и `error` (в т.ч. network_error
  и timeout — они приходят как `error`); результат по ИНН и результат по ОГРН
  кэшируются отдельно, повторный запуск берёт оба из кэша.
* Автопоиск колонок: точное имя (`ИНН`, `ОГРН`, `ОГРНИП`) → затем «содержит»
  с выбором колонки по числу валидных значений (чтобы `ИНН/КПП` не перебил ИНН).
  `Идентификатор`/`Код` берутся только при точном совпадении имени: иначе
  «Идентификатор СПАРК» уехал бы в DaData как идентификатор.
* Оба идентификатора в строке — приоритет ИНН (`--prefer inn`, дефолт) или
  ОГРН (`--prefer ogrn`), fallback всегда только на ОГРН/ОГРНИП.
* `--column` сохранён как синоним `--inn-column` с предупреждением об устаревании.
