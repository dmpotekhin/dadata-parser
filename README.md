# DaData: выгрузка организаций по списку ИНН/ОГРН + фильтр по ОКВЭД 56/46

Скрипт `dadata_okved_filter.py` берёт Excel-файл со списком организаций, последовательно
(строго по одному запросу, без потоков и асинхронщины) запрашивает DaData
`findById/party`, вытаскивает основной и дополнительные ОКВЭД и оставляет только те
организации, у которых ОКВЭД начинается на `56` или `46`.

**Выбор идентификатора.** Для каждой строки скрипт решает, что отправить в DaData:
сначала ИНН (10 или 12 цифр), а если он пустой или невалидный — ОГРН юрлица (13 цифр)
или ОГРНИП (15 цифр). Если валидного идентификатора нет, строка получает статус
`invalid_id`, запрос по ней не отправляется и суточный лимит не тратится. Колонки
находятся автоматически (`--search-by auto` — режим по умолчанию) или задаются явно
(`--inn-column`, `--ogrn-column`). Приоритет переключается флагом `--prefer ogrn`, а
неудачный поиск по ИНН повторяется по ОГРН из той же строки при `--fallback-to-ogrn`.

Скрипт сам следит за лимитами DaData: **не более 30 запросов в минуту** (скользящее
окно 60 секунд + минимальный интервал 2 секунды) и **не более 10 000 запросов в сутки**
(счётчик с привязкой к дате и часовому поясу). При достижении лимита он корректно
останавливается, сохраняет прогресс и продолжает работу при следующем запуске.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Требуется Python 3.10+.

## Токен DaData

Токен НЕ хранится в коде. Возьмите его в личном кабинете DaData
(<https://dadata.ru/profile/#info>).

**Рекомендуется: файл `.env` рядом со скриптом.** Скрипт читает его сам
(`python-dotenv` из `requirements.txt`), токен не попадает ни в историю команд,
ни в список процессов:

```bash
cp .env.example .env
chmod 600 .env                       # читать может только владелец
# затем откройте .env в редакторе и вставьте токен:
# DADATA_TOKEN=ваш_токен
```

Файл `.env` уже в `.gitignore` (как и `.env.local` и прочие `.env.*`), шаблон
`.env.example` — в репозитории, самого токена в нём нет.

Приоритет источников: `--token` → переменная окружения `DADATA_TOKEN` → `.env`
(уже заданная переменная окружения никогда не перезаписывается файлом).

**Альтернатива: переменная окружения** (удобно на сервере/в CI):

```bash
export DADATA_TOKEN="ваш_токен"            # Linux/macOS
set DADATA_TOKEN=ваш_токен                 # Windows cmd
$env:DADATA_TOKEN="ваш_токен"              # Windows PowerShell
```

**Альтернатива для macOS: Keychain** (токена нет на диске в открытом виде):

```bash
security add-generic-password -a "$USER" -s dadata-token -w 'ваш_токен' -U
DADATA_TOKEN="$(security find-generic-password -a "$USER" -s dadata-token -w)" \
  python3 dadata_okved_filter.py --input inn.xlsx --output result.xlsx
```

**Не рекомендуется: `--token ваш_токен`** — попадает в историю команд и в список
процессов. В любом случае в логах токен всегда маскируется (`abcd...7890`), а в
выходной файл и state-файл не пишется вовсе.

## Запуск

```bash
# Linux/macOS
python3 dadata_okved_filter.py --input список.xlsx --output результат.xlsx --search-by auto --prefer inn

# Windows cmd
set DADATA_TOKEN=ваш_токен
python dadata_okved_filter.py --input список.xlsx --output результат.xlsx --search-by auto --prefer inn

# Windows PowerShell
$env:DADATA_TOKEN="ваш_токен"
python dadata_okved_filter.py --input список.xlsx --output результат.xlsx --search-by auto --prefer inn
```

По умолчанию берётся ИНН, ОГРН подключается только если ИНН нет или он невалиден.

Полезные варианты:

```bash
# приоритет ОГРН (даже если в строке есть ИНН)
python3 dadata_okved_filter.py --input in.xlsx --output out.xlsx --prefer ogrn

# если по ИНН not_found/error — повторить по ОГРН из той же строки
python3 dadata_okved_filter.py --input in.xlsx --output out.xlsx --prefer inn --fallback-to-ogrn

# явные колонки (полезно, если автопоиск промахнулся)
python3 dadata_okved_filter.py --input in.xlsx --output out.xlsx --inn-column "ИНН компании" --ogrn-column "ОГРН"

# посмотреть план и локальную валидацию, не тратя ни одного запроса
python3 dadata_okved_filter.py --input in.xlsx --output план.xlsx --dry-run

# тестовый прогон на 100 строках
python3 dadata_okved_filter.py --input in.xlsx --output тест.xlsx --limit 100

# фильтровать только по основному ОКВЭД
python3 dadata_okved_filter.py --input in.xlsx --output out.xlsx --only-main

# медленнее, чем позволяют лимиты (10 rpm, пауза 3 секунды)
python3 dadata_okved_filter.py --input in.xlsx --output out.xlsx --max-per-minute 10 --sleep 3

# продолжить после дневного лимита / падения (resume включён по умолчанию)
python3 dadata_okved_filter.py --input in.xlsx --output out.xlsx --resume

# обработать заново, игнорируя state-файл
python3 dadata_okved_filter.py --input in.xlsx --output out.xlsx --no-resume
```

## Параметры командной строки

|---|---|---|
| `--input` | — (обязателен) | Входной Excel-файл |
| `--output` | `<input>_dadata.xlsx` | Выходной Excel-файл |
| `--sheet` | первый лист | Имя листа |
| `--search-by` | `auto` | Режим поиска: `auto` — сам находит колонки ИНН и ОГРН/ОГРНИП |

| `--only-main` | выключен | Фильтровать только по основному ОКВЭД |
| `--max-per-minute` | `30` | Максимум запросов в минуту |
| `--daily-limit` | `10000` | Максимум запросов в сутки |
| `--state-file` | `dadata_state.json` | Файл состояния (checkpoint) |
| `--resume` / `--no-resume` | `--resume` | Пропускать уже обработанные ИНН |
| `--timezone` | `Europe/Moscow` | Часовой пояс для суточного счётчика |
| `--sleep` | `0` | Доп. пауза; фактическая пауза = `max(sleep, 60/max-per-minute)` |
| `--limit` | `0` (все) | Обработать только первые N строк |
| `--dry-run` | выключен | Показать план без запросов к API |
| `--okved-prefixes` | `56,46` | Префиксы ОКВЭД через запятую |
| `--progress-every` | `20` | Как часто печатать прогресс (в строках) |

| `--timeout` | `10` | Таймаут HTTP-запроса, секунды |
| `--max-retries` | `5` | Максимум попыток запроса |

лимит или квота DaData, `3` — ошибка авторизации, `130` — прерывание (Ctrl+C).

43 rpm при реальном интервале 2 с = 30 rpm). Пока запросов меньше двух, выводится
`н/д (мало запросов)`.

## Как соблюдаются лимиты

* **Частота.** Класс `DaDataRateLimiter` хранит времена последних запросов в
  `collections.deque` (скользящее окно 60 секунд) и перед каждым запросом считает
  паузу: `max(время до выхода самого старого запроса из окна, минимальный интервал 60/max_per_minute, --sleep)`.
  Пауза обновляется в цикле, поэтому окно никогда не переполняется.
* **Учёт запросов.** Через `acquire()` проходит **каждый** фактический вызов API,
  включая повторы при 429/5xx, — именно это число пишется в дневной счётчик.
  Локальная валидация идентификаторов (пробелы, дефисы, длина ИНН/ОГРН)
  запросов не тратит: строки со статусом `invalid_id` в счётчик не попадают.
* **Сутки.** Дата берётся в часовом поясе `--timezone`. При смене даты дневной
  счётчик обнуляется, а кэш и список обработанных ИНН сохраняются.
* **Retry-After.** При HTTP 429 сначала используется заголовок `Retry-After`;
  если его нет — ожидание до освобождения слота в окне 60 секунд.
* **403.** Если в теле есть признаки лимита/квоты — аккуратная остановка с кодом
  2; иначе это ошибка токена (код 3) и повторы не выполняются.
* **Стоп по лимиту.** Если на сутки осталось меньше запросов, чем строк, скрипт
  обрабатывает доступное количество, пишет состояние и завершает работу с
  сообщением: `Достигнут дневной лимит DaData. Продолжите обработку позже или
  увеличьте лимит в личном кабинете.`

## Checkpoint и продолжение

Состояние пишется в `dadata_state.json` (параметр `--state-file`):

```json
{
  "version": 2,
  "date": "2026-10-15",
  "used_today": 137,
  "processed_inns": ["inn:7707083893", "ogrn:1027700000000", "..."],
  "last_request_time": "2026-10-15T14:00:19+03:00",
  "cache": {
    "inn:7707083893": {"status": "ok", "name": "ООО \"Ромашка\"", "okved_main": "56.10", "okved_extra": [], "error": ""},
    "ogrn:102770000012345": {"status": "not_found", "name": "", "okved_main": "", "okved_extra": [], "error": ""}
  }
}
```

* Состояние сохраняется после каждого запроса, каждые `--save-every` строк, при
  Ctrl+C и перед остановкой по дневному лимиту.
* Выходной файл (`Все` / `Отфильтровано` / `Статистика`) перезаписывается каждые
  `--save-every` строк и в конце, поэтому результаты не теряются при падении.
* Ключ кэша содержит тип идентификатора (`inn:`, `ogrn:`, `ogrnip:`), поэтому
  один и тот же номер, отправленный как ИНН и как ОГРН, не путается.
  Если поиск шёл по ИНН с фолбэком на ОГРН, сохраняются **оба** результата —
  следующий запуск не повторит ни одного запроса.
* Ключи прежнего формата (голый ИНН) при первом запуске автоматически
  переезжают в `inn:…` — прогресс не теряется.
* Дубликаты идентификатора в файле берутся из кэша — повторных запросов нет.
* Внутри одного запуска запоминается результат **любого** статуса, поэтому три
  строки с одним и тем же «плохим» ИНН тратят один запрос, а не три.
* Между запусками (в `state.json`) сохраняются только успешные результаты
  (`ok`, `not_found`): строки с сетевой/HTTP-ошибкой при следующем запуске
  запрашиваются заново. Строки, не дошедшие до обработки, остаются в статусе
  `pending` и обрабатываются при resume.
* Если `state.json` потерян, но есть выходной файл, кэш восстанавливается из листа
  `Все` (в логе: «Кэш восстановлен из ...»).

## Выходной файл

Исходные колонки + служебные:

| Колонка | Содержимое |
|---|---|
| `Использованный тип поиска` | `inn`, `ogrn` или `ogrnip` — что фактически ушло в DaData |
| `Причина выбора идентификатора` | «INN найден и валиден», «INN пустой, использован ОГРН», «INN невалидный, использован ОГРН», «INN not_found, fallback на ОГРН», «INN error, fallback на ОГРН», «ОГРН найден и валиден (приоритет ОГРН)», «ОГРН пустой/невалидный, использован ИНН», «Оба идентификатора невалидны», «Оба идентификатора пусты» |
| `ИНН из строки` / `ОГРН из строки` | Значения ячеек как есть (для сверки с источником) |
| `Нормализованный ИНН` / `Нормализованный ОГРН` | Только цифры: пробелы, дефисы и `.0` убраны (dtype=str, ведущие нули сохраняются) |
| `Найденный ИНН` | `data.inn` организации из ответа |
| `Найденный ОГРН` | `data.ogrn` из 13 цифр (юрлицо) |
| `Найденный ОГРНИП` | `data.ogrn` из 15 цифр (ИП); отдельного поля `data.ogrnip` у DaData нет |
| `Найденный КПП` | `data.kpp` (у ИП отсутствует) |
| `Название` | Название организации из DaData |
| `Основной ОКВЭД` | `data.okved` |
| `Дополнительные ОКВЭД` | `data.okveds` через `; ` (поддерживаются и объекты с `code`, и строки) |
| `Статус` | `ok`, `not_found`, `invalid_id`, `error`, `auth_error`, `quota_exceeded`, `pending`, `dry_run` |
| `Ошибка` | Текст ошибки (сеть, HTTP-код, невалидный JSON и т.п.) |
| `Fallback использован` | `да`, если после неудачного поиска по ИНН строка была найдена по ОГРН |
| `Ключ запроса` | Ключ кэша (`inn:7707083893`), видно, по какому номеру шёл запрос |
| `Совпадает основной` | Основной ОКВЭД начинается на 56 или 46 |
| `Совпадает любой` | Основной или любой дополнительный ОКВЭД начинается на 56 или 46 |
| `Использовано запросов` | Значение дневного счётчика на момент обработки строки |
| `Дата обработки` | Время обработки строки в формате ISO с часовым поясом |

Листы: `Все` (все строки), `Отфильтровано` (совпадения 56/46 по выбранному
критерию), `Статистика` (итоговые счётчики).

## Защиты и гарантии

* **Дневной счётчик не сбрасывается случайно.** `--no-resume` пропускает кэш, но
  не обнуляет суточный учёт: `used_today` берётся из `state.json` независимо от
  resume. Сброс происходит только при смене даты (в этот день счётчик начинается
  с нуля, кэш при этом сохраняется).
* **Один писатель на state-файл.** На время прогона берётся блокировка
  (`<state-file>.lock`, `flock`/`msvcrt`); второй процесс с тем же state-файлом
  сразу завершается с кодом `1` и сообщением «уже используется другим процессом»,
  не сделав ни одного запроса. Блокировка снимается при выходе и при Ctrl+C.
* **Excel-формулы не попадают в отчёт.** Значения, начинающиеся с `=`, `+`, `-`,
  `@`, записываются как текст (защита от formula injection), само значение при
  этом сохраняется.
* **Идентификаторы не портятся.** Колонки читаются как текст (`dtype=str`),
  ведущие нули, 12-значные ИНН и 15-значные ОГРНИП сохраняются. Валидны строго
  10/12 ASCII-цифр для ИНН и 13/15 для ОГРН/ОГРНИП: похожие символы
  (арабо-индийские цифры, буквы) не проходят проверку.
* **Строка без валидного идентификатора не тратит лимит.** Если и ИНН, и ОГРН
  пусты или невалидны, запись получает статус `invalid_id` с причиной в отчёте,
  а запрос к DaData не отправляется.
* **Служебные номера не уходят в DaData.** Колонки `Идентификатор` и `Код`
  используются как источник только при точном совпадении имени, поэтому
  «Идентификатор СПАРК» в запрос не попадает. Для остальных кандидатов
  (`ИНН`, `ОГРН`, `ОГРНИП`, имена, содержащие «ИНН»/«ОГРН») выбирается колонка
  с наибольшим числом валидных значений, а её имя и число валидных ячеек
  печатаются в лог первой строкой.
* **Токен не утекает.** Только `https`; `http` разрешён исключительно для
  `127.0.0.1`/`localhost` (тесты). В логах токен маскируется, в файл попадает
  лишь признак «токен задан».
* **Прокси.** Для внешних адресов уважаются переменные окружения
  (`HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY`); для loopback-адресов (мок-сервер в
  тестах) они игнорируются, иначе запрос ушёл бы наружу вместо локального сервера.

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

* `tests/test_rate_limiter.py` — арифметика лимитов на фейковых часах: не более
  30 запросов в любое окно 60 секунд, минимальный интервал 2 секунды,
  `--sleep` не может увеличить частоту, остановка по дневному лимиту, учёт
  последнего запроса предыдущего запуска при resume.
* `tests/test_cli_integration.py` — сквозные прогоны CLI против мок-сервера
  (`tests/mock_dadata.py`, эмуляция DaData): нормализация ИНН, кэш дубликатов,
  повторы при 500/429 с `Retry-After`, битый JSON, HTTP 400, 403/квота,
  фильтрация 56/46, `--only-main`, дневной лимит + resume, Ctrl+C + resume,
  `--dry-run`, восстановление кэша из выходного файла.
* `tests/test_review_fixes.py` — регрессии на дефекты, найденные независимым
  ревью: `--no-resume` не обнуляет суточный счётчик, второй процесс
  отбрасывается блокировкой state-файла, дубликаты «плохих» ИНН тратят один
  запрос, формула-инъекция нейтрализуется, ведущие нули и не-ASCII цифры,
  отказ от небезопасного `http://` для внешнего хоста, учёт повторов при
  сетевой ошибке, сброс дневного счётчика при смене даты без потери кэша.
* `tests/test_identifier_selection.py` — выбор идентификатора: приоритет ИНН,
  переход на ОГРН/ОГРНИП при пустом и невалидном ИНН, `invalid_id` без запроса,
  `--prefer ogrn`, `--fallback-to-ogrn` (not_found и 5xx) с кэшированием обоих
  результатов, фолбэк из кэша, ключи `inn:`/`ogrn:`/`ogrnip:` и миграция старого
  state-файла, автопоиск колонок и защита от «Идентификатора СПАРК», новые
  колонки отчёта, `--dry-run` с типом поиска.
* Всего 46 тестов, сеть не нужна: внешних обращений нет, всё через мок.
* Мок-сервер можно поднять вручную: `python3 tests/mock_dadata.py`, тогда
  endpoint задаётся через `DADATA_API_URL` (переменная окружения или `--api-url`).

## Ограничения

* `findById/party` принимает и ИНН (10/12 цифр), и ОГРН/ОГРНИП (13/15 цифр):
  проверено живым запросом — поиск по ОГРНИП возвращает ту же организацию, что и
  поиск по её ИНН. Поле `data.ogrn` содержит ОГРН юрлица (13 цифр) либо ОГРНИП
  ИП (15 цифр), отдельного `data.ogrnip` у DaData нет.
* Заметная часть списка ИП может не найтись в DaData — такие строки получают
  статус `not_found` без повторов; спасает `--fallback-to-ogrn`, если в строке
  есть ОГРН.
* Скрипт намеренно однопоточный: ускорение за счёт параллельных запросов
  нарушило бы лимит 30 rpm.
